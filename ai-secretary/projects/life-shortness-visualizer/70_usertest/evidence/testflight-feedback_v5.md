### #1 週の記録：星タップがリアルタイムに反映されない

**内容**
週の記録にて星をタップした時、リアルタイムで変更されない。

**分類**: バグ（UI更新）

**実装方針**
- `@State` / `@Published` の更新が View に伝播していない可能性が高い
- タップ時に直接データモデルを更新し、SwiftUI の再描画を確実にトリガーする
- 保存処理（CoreData / UserDefaults）を非同期で行っている場合、UI更新と保存を分離する

**修正手順**
1. 星タップのハンドラーで `@State` or `@Published` 変数を即時更新する
2. 永続化処理は更新後に非同期で実行する
3. View が `ObservableObject` を正しく参照しているか確認する（`@ObservedObject` / `@StateObject`）

**実装修正済み** ✅
- `WeekDetailViewModel.setStars()` 内で保存後に `weekRecord = try await repository.fetchWeekRecord(lifeWeekIndex:)` を追加
- `weekRecord` プロパティを再代入することで `@Observable` が差分を検知し SwiftUI が再描画される

### #2 週の記録ボタンで選択中の円が今週にリセットされる

**内容**
週の記録ボタンを押すと、選択した円（週）が今週に戻ってしまう。
画面が完全に切り替わった時（統計・設定）だけ今週に戻すべき。

**分類**: バグ（状態管理）

**実装方針**
- 選択中の週（`selectedWeek`）を TabView の外側（親ビュー or ViewModel）で管理する
- タブ切り替えの種別を判定し、「同じタブ内の再タップ」では selectedWeek を変更しない
- リセット条件を「他タブ（統計・設定）から週の記録タブに戻ってきた時」に限定する

**修正手順**
1. `selectedWeek` の管理箇所を TabView の子ビューから親に移動する
2. タブ切り替えの `onChange(of: selectedTab)` で「前のタブが統計/設定だった場合のみ」selectedWeek をリセットする
3. 週の記録タブ内のボタンタップでは selectedWeek を変更しない

**実装修正済み** ✅
- `GridViewModel` に `sheetLifeWeekIndex: Int` を追加（シートに渡す週を selectedLifeWeekIndex と分離）
- `selectCurrentWeek()` を `sheetLifeWeekIndex = currentLifeWeekIndex` のみに変更（selectedLifeWeekIndex を触らない）
- `selectWeek()` は引き続き両方を更新（グリッドタップ時は選択位置も移動）
- `GridView` のシートを `viewModel.sheetLifeWeekIndex` で開くよう変更

### #3 カテゴリー変更時に丸の色が変わらない／カテゴリー増減時の色設計

**内容**
カテゴリーを変更した際、人生カレンダーの丸の色が変わらない。
カテゴリーを増やしたり減らした場合の色設計をどうすべきか。

**分類**: バグ＋設計相談

---

#### 設計方針の結論：動的参照 ＋ ソフトデリート

カテゴリーを完全に削除するのではなく「アーカイブ（非表示）」として残す。
丸の色は常にカテゴリーテーブルから動的に参照する。

**採用理由**
- カテゴリーのIDが記録に残るため、過去の評価内容（どのカテゴリーだったか）が失われない
- colorCode を記録に別途保存する必要がなく、実装がシンプル
- バグの原因となる「色の更新漏れ」が発生しない

---

#### 各方式の比較

| 方式 | 実装量 | バグリスク | 過去の色の保持 | カテゴリー削除時 |
|------|--------|-----------|--------------|---------------|
| **動的参照 + ソフトデリート（採用）** | 少 | 低 | カテゴリー色に追従 | アーカイブとして残す |
| スナップショット（colorCode保存） | 中 | 中 | 記録時点の色を完全保持 | 削除済み色がそのまま残る |
| 動的参照のみ（完全削除あり） | 少 | 高 | カテゴリー色に追従 | 孤立参照が発生 |

---

#### データモデル

```swift
struct Category {
    let id: UUID
    var name: String
    var color: String      // hex カラーコード
    var isArchived: Bool   // true = 削除済み（過去記録の参照用に残す）
}

struct WeekRecord {
    let weekId: String     // "2026-W01" 形式
    var categoryId: UUID?  // カテゴリーのIDのみ保存（色は保存しない）
    var rating: Int
}
```

---

#### 動作仕様

| 操作 | 丸の色の動作 |
|------|------------|
| カテゴリーの色を変更 | 過去・現在の全記録に反映される |
| カテゴリーをアーカイブ（削除） | 過去記録の色はアーカイブ時点の色のまま表示される（色を変えないため） |
| 過去記録を編集してカテゴリー変更 | 選択した新カテゴリーの色に更新される |
| 過去記録を編集（カテゴリーは変えない） | 色は変わらない |
| 新規カテゴリー追加 | 既存記録には影響なし |

---

#### 実装手順

1. **`Category` モデルに `isArchived: Bool` を追加する**
   - 既存の削除処理を `isArchived = true` に置き換える
   - カテゴリー選択UIでは `isArchived == false` のみ表示する

2. **人生カレンダーの色参照ロジックを修正する**
   - 現在: 色が更新されない原因を特定する（直接 color を持っている場合はここを修正）
   - 修正後: `weekRecord.categoryId` → `categoryStore.find(id:)` → `category.color` の参照チェーンを確立する

3. **アーカイブされたカテゴリーの表示**
   - 過去記録の詳細表示時に「（削除済み）カテゴリー名」と表示する
   - 編集画面ではアーカイブ済みカテゴリーをグレーアウトして選択不可にする

**実装修正済み** ✅
- 丸の色は `averageStars` から決定されるため、カテゴリー変更自体が色を変える仕組みではなかった
- 実際のバグ原因: シート閉鎖後に `GridViewModel.weekRecordMap` が更新されないため丸の色が変わらない
- `GridView` に `.onChange(of: viewModel.isWeekDetailPresented)` を追加し、シート閉鎖時に `reloadWeekRecords()` を呼ぶよう修正
- `GridViewModel.reloadWeekRecords()` を新規追加（選択状態を維持したままデータのみ再取得）
- `Category.isActive` によるソフトデリートは既に実装済みのため変更不要

---

#### 注意点

- カテゴリーの色を変更すると過去の記録の色も変わる。これはこの設計の仕様であり、意図した動作。
- 「過去の色を絶対に変えたくない」要件が将来発生した場合は、`colorCode` を `WeekRecord` に追加するスナップショット方式に移行する。その際は既存データへの `colorCode` 埋め込みマイグレーションが必要。

- カテゴリーの色を変更すると過去の記録の色も変わる。これはこの設計の仕様であり、意図した動作。
-> カテゴリーの色を変更するとはなんですか。過去のカテゴリーを変更すると過去の記録の色が変わるという認識で良いですか？

**返信**

「カテゴリーの色を変更する」は2つの操作を指しており、区別が必要です。

| 操作 | 意味 | 影響範囲 |
|------|------|---------|
| A. カテゴリー自体の色設定を変える | 設定画面で「仕事」カテゴリーの色を赤→青に変える | そのカテゴリーを使っている**全記録**（過去・現在）の丸の色が変わる |
| B. 過去の記録のカテゴリーを変える | 週の記録編集画面で「仕事」→「プライベート」に変える | **その週の記録だけ**の丸の色が変わる |

コメントの注意点は **操作A** を指しています。
「仕事」カテゴリーの色設定を変えると、過去にも「仕事」として記録した全週の丸の色が変わる、という仕様です。

ご認識の「過去のカテゴリーを変更すると色が変わる」は **操作B** に相当し、これも正しいです。
ただし影響はその週だけです。
