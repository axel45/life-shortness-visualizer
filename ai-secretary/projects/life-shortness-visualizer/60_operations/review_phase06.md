## A. リリース手順

- [○] リリース手順が「この手順書だけで別の人が実行できる」粒度で記述されているか → Archive → Distribute → App Store Connect設定の各ステップをコマンド・UI操作レベルで記述
- [○] 本番環境の設定変数・シークレットの設定方法が記載されているか → APIキーなし。Bundle ID・CloudKit Containerの設定方法を記載
- [○] DBマイグレーションの実行手順と確認方法が記載されているか → SwiftData VersionedSchemaの方針をdb_design.md参照で明示
- [○] リリース前チェックリスト（デプロイ前に確認すべき項目一覧）があるか → 8項目のチェックリストを記載（CFBundleVersion・Info.plist・CloudKit Production・証明書・スクリーンショット等）
- [○] ダウンタイムが発生する場合の手順があるか → サーバーレス構成のためダウンタイムなし。App Store審査中は旧バージョン継続提供と明示

**A: 5/5**

## B. ロールバック・緊急対応

- [○] ロールバック手順が具体的に記載されているか → App Store Connect での旧ビルド再申請手順（3ステップ）を記載
- [○] DBマイグレーションのロールバック手順が定義されているか → VersionedSchemaで破壊的変更を回避する方針を明示
- [○] 障害発生時のエスカレーションフローが定義されているか → 個人開発のため Shogo 単独対応フローを定義
- [○] 障害レベル定義（P0〜P3）と対応時間が記載されているか → P0〜P3の4段階・対応時間（即座〜次回更新）を定義
- [!] 過去のリリース記録（バージョン・日時・変更内容）を追跡できる仕組みがあるか → App Store Connect が自動的にビルド履歴を管理するが、変更内容の記録方法が未定義
  > **解消不要理由**: App Store Connect のビルド一覧がリリース記録を自動管理する。変更内容は git commit メッセージで追跡可能。個人開発では別途変更ログ管理は過剰要件。

**B: 4/5**

---

## C. 監視・アラート設計

- [○] 監視対象メトリクスが定義されているか → クラッシュレート・App Storeレビュー・CloudKit使用量・KPIの4項目を定義
- [○] 企画書のKPIを計測するためのイベント計測が実装されているか → WeekRecord.createdAt と onboardingCompletedAt で4週継続率・初回記録完了率を計算可能（requirements.md 3.5参照）
- [○] アラート条件（閾値・通知先・通知方法）が定義されているか → クラッシュ1%・レビュー3.0以下の閾値とApp Store Connect通知を定義
- [!] ログ収集・検索の仕組みが整っているか → App Store Connect Crashesのみ。アプリ内のエラーログをリモートで収集する仕組みがない
  > **解消不要理由**: サーバーレス構成のためサーバーサイドログは存在しない。アプリ内エラーはViewModel.errorMessageでUI表示済み。クラッシュはApp Store Connectのシンボリケートログで確認可能。Firebaseなどの外部ログ収集はプライバシーポリシー上の負担が増加するため採用しない（個人アプリ方針）。
- [○] ヘルスチェックエンドポイントが実装・監視されているか → サーバーレスのためN/A（合格扱い）

**C: 4/5**

## D. 運用手順

- [○] 定期メンテナンス作業の手順があるか → 週次（クラッシュ確認・レビュー返信）・月次（KPI確認・CloudKit使用量）を定義
- [○] ユーザーからの問い合わせ対応フローがあるか → App Storeレビュー返信のみ・1週間以内回答目標を設定
- [○] データバックアップの取得・復元手順が記載されているか → iCloud自動バックアップをAppleが管理することを明示
- [○] 外部サービス障害時の対応方針があるか → iCloud障害: ローカル保存継続（requirements.md 2.9）・写真権限拒否: エラーUI表示済み（E01）

**D: 4/4**

---

## E. ストア申請・コンプライアンス

- [○] App Store申請に必要な情報が揃っているか → アプリ名・サブタイトル・説明文・キーワード・カテゴリ・年齢制限・スクリーンショット構成（3枚）を定義
- [!] プライバシーポリシー・利用規約が作成され、アプリ内からリンクされているか → プライバシー方針の文章は作成済み。独立したURL（Webページ）が未作成
  > **解消不要理由**: App Store申請時に必要なため、申請前に GitHub Pages または Notion Public ページでプライバシーポリシーを公開する（申請直前作業）。設計・実装フェーズで先行作成する必要はない。
- [○] 個人情報保護法・GDPRへの対応方針が確認されているか → 外部送信なし・生年月日のみローカル+iCloud保存・Appleのデータ収集基盤に準拠
- [○] 健康・医療情報のガイドライン準拠 → 健康・医療アプリではないためN/A（合格扱い）
- [○] 年齢制限・コンテンツレーティングが適切か → 4+（暴力・成人向けコンテンツなし）を設定

**E: 4/5**
