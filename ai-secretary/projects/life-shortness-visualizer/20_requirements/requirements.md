# 人生の短さ可視化アプリ 要件定義書

作成日: 2026年7月29日
更新日: 2026年8月4日
ステータス: 確定

---

## 1. アプリ概要

自分がこれまでの人生をどのように生きてきたか、そして人生全体の中で今どの地点にいるのかを、視覚的に実感できるアプリ。人生グリッドを壁紙として毎週自動更新し、目標管理機能と組み合わせて構成する。

**ターゲットユーザー**: 企画書で定義した田中誠ペルソナ（32歳・ITコンサル・目標管理習慣を持つビジネスパーソン）を参照。詳細は `10_planning/planning.md` のペルソナ定義を参照すること。

## 2. 機能要件

### 2.1 画面構成

| 画面 | 概要 |
|------|------|
| グリッド画面（メイン） | 人生80年×52週の丸グリッドを表示。ライフステージバー・下部統計を含む |
| 週詳細シート | 選択した週の目標カテゴリーごとの★評価を記録・閲覧するボトムシート |
| 統計シート | カテゴリー別達成率推移グラフ・ストリークを表示するボトムシート |
| 設定画面 | プロフィール・ライフステージ・カテゴリー・壁紙ガイドの管理 |
| オンボーディング | 初回起動時の生年月日入力・壁紙設定ガイド・カテゴリー設定 |

### 2.2 グリッド表示

- 1行 = 1年、1つの丸 = 1週間（横52列 × 縦80行 = 4,160個）
- 想定寿命：80歳（設定画面で変更可能）

**グリッド座標系（人生基準）**

| 軸 | 意味 | 起点 |
|----|------|------|
| 行（縦） | 人生の年（0行目 = 誕生年） | row = lifeWeekIndex / 52 |
| 列（横） | その年の何週目か（0列目 = 誕生週） | col = lifeWeekIndex % 52 |

- **グリッドはカレンダー年ではなく人生を基準とする**
- 左上 (row=0, col=0) = 誕生週（誰にとっても最初の丸）
- 現在週 = `floor((today − birthDate).days / 7)`（誕生日からの通し週番号）
- 表示日付範囲 = `birthDate + lifeWeekIndex × 7` 〜 `+ 6日`
- ISO 8601 のカレンダー週とは一致しない（6月23日生まれなら1行目は6月〜翌6月で構成される）

**丸の色分けロジック（全カテゴリーの★平均で判定）**

| 状態 | 表示 |
|------|------|
| 未来の週 | 白枠線の黒丸（塗りなし） |
| 目標未設定 または 平均★3未満 | グレー |
| 平均★3以上 | 白 |
| 平均★4以上 | 銀色 |
| 全カテゴリー★5 | 金色 |

**ライフステージバー（グリッド左側）**

| ステージ名 | デフォルト年齢 |
|-----------|-------------|
| 未就学児 | 0–6歳 |
| 小学校 | 6–12歳 |
| 中学 | 12–15歳 |
| 高校 | 15–18歳 |
| 大学 | 18–22歳 |
| 社会人なりたて | 22–27歳 |
| プロジェクトリーダー（仮） | 27–32歳 |
| マネージャー（仮） | 32–40歳 |
| マネージャー以降のキャリア | 40–65歳 |
| 老後 | 65歳– |

- ステージ名（最大20文字）・開始年齢（0〜84歳の整数）・色（ColorPickerで選択）をユーザーがカスタマイズ可能
- ライフステージバーをタップ → 統計シートを表示

**選択インジケーター（ゴールドリング）**

v2.0 にて赤丸 → ゴールドリングに変更済み。

| タイミング | 挙動 |
|-----------|------|
| アプリ起動時 | 常に今週（現在の lifeWeekIndex）にリセット |
| 丸をタップ | タップした週に即時移動 + 週詳細シートを表示 |
| FABボタンをタップ | 今週の週詳細シートを表示 |

**下部統計バー：廃止**

グリッド画面に統計バーは表示しない（v2.0で廃止）。
人生消費率は S03 統計画面の累計記録セクションに表示する。

### 2.3 週次目標管理

- 目標カテゴリーはユーザーが自由に設定（最大5カテゴリー）
- デフォルト候補：運動・食事・睡眠・仕事
- 各カテゴリーの達成度を**★1〜★5の5段階**で手動記録
- 記録は週詳細シートから行う

### 2.4 統計・グラフ

- カテゴリーごとの達成率推移グラフ（Swift Charts）
- 連続達成記録（ストリーク）表示
- 過去の任意の週の詳細を閲覧可能

### 2.5 壁紙自動更新

- AppIntents を実装し「壁紙を生成して保存」アクションをショートカットAppに公開
- ユーザーが初回1回だけショートカット自動化を設定（毎週月曜 朝7時）
- 以降はアプリを開かなくても毎週自動でホーム画面・ロック画面の壁紙が更新される
- 生成した壁紙画像は写真ライブラリの「Life in Weeks」アルバムに保存
- 壁紙はiPhone画面のネイティブ解像度でレンダリング（PNG形式）

### 2.6 オンボーディング

| ステップ | 内容 | スキップ |
|---------|------|---------|
| O00 | スプラッシュ（468個の装飾ドットのウェーブアニメーション + 「始める」ボタン） | 不可（必須） |
| O01 | 生年月日入力 + 想定寿命設定（1画面。寿命は±1ボタンで60〜120歳、デフォルト80歳。残り週数をリアルタイム表示） | 不可（必須） |
| O01.5 | グリッド生成アニメーション（ピーク体験）。ユーザーの実際のグリッド全体（lifeExpectancy行×52列）を過去週から順番にスキャンしながら描画。現在週でゴールドリング表示。完了時にnotificationFeedback(.success)。Reduce Motion 対応 | 不可 |
| O02 | カテゴリー設定 | 可 |
| O03 | 壁紙設定ガイド（ショートカット設定手順の案内） | 可（グリッド画面のバナーから随時） |

- O02をスキップした場合、設定画面の壁紙ガイドから再度アクセス可能

### 2.7 設定

- プロフィール：生年月日・想定寿命の変更
- ライフステージ管理：既存ステージをタップして編集シートを表示。編集フォームはステージ名（TextField・最大20文字）・開始年齢（Stepper 0〜84歳）・終了年齢（Stepper 開始年齢+1以上）・色（ColorPicker）で構成。保存時に年齢重複バリデーションを実施。スワイプ削除も可能。デフォルト10件はアプリ初期状態として存在
- カテゴリー管理：追加・削除・並び替え（最大5個）
- 壁紙設定ガイドへのアクセス

### 2.8 データ削除

「すべてのデータを削除」実行時の仕様：

| 項目 | 仕様 |
|------|------|
| 削除対象エンティティ | UserProfile / LifeStage / Category / WeekRecord / CategoryRating の全件 |
| iCloudデータ | ローカルと同様に全削除（CloudKit上のレコードも削除） |
| UserDefaultsフラグ | `wallpaperShortcutConfigured` を false にリセット |
| 削除後の状態 | オンボーディング（O00）から再スタート。既存ショートカットはユーザーが手動削除する必要あり |
| 確認ステップ | 実行前に確認ダイアログを表示（「この操作は元に戻せません」を明示）。キャンセル可能 |
| 写真ライブラリ | アプリからは削除しない（壁紙画像はユーザーが手動削除）|

### 2.9 エラー・例外フロー

**写真ライブラリ権限を拒否された場合**

| タイミング | 挙動 |
|-----------|------|
| 壁紙生成アクション実行時に権限なし | インラインエラーメッセージ「写真ライブラリへのアクセスが許可されていません」を表示 |
| エラーメッセージのCTA | 「設定を開く」ボタンを表示。タップするとiOS設定アプリのアプリ権限画面に遷移 |
| 権限取得前のフロー継続 | 壁紙生成・保存はスキップ。記録データへの影響なし |

**iCloud未接続・未サインインの場合**

| タイミング | 挙動 |
|-----------|------|
| アプリ起動時 | サイレント（通知しない）。ローカル保存で動作継続 |
| 同期失敗 | iOSのシステム通知に委ねる（アプリ側での追加通知はしない） |
| ユーザーへの案内 | 設定画面にiCloud同期状態は表示しない。「オフラインでも動作します」の一言のみ記載 |

### 2.10 プッシュ通知

| 項目 | 仕様 |
|------|------|
| 目的 | 週次記録の習慣化を促すリマインダー |
| 通知タイミング | 毎週日曜日 20:00（ユーザーが設定画面で変更可能） |
| 通知文言例 | 「今週の記録がまだ未入力です。1分で振り返りましょう」 |
| 通知文言方針 | 敬語なし・絵文字なし・40文字以内・プレッシャーを与えない肯定的トーン |
| 権限取得タイミング | オンボーディング（O02カテゴリー設定）完了後に初回リクエスト |
| 権限を拒否された場合 | 通知なしで動作継続。設定画面から再度 iOS 設定へ誘導するリンクを提供 |
| 通知をタップした場合 | アプリが起動し、S02 週詳細シート（今週）を直接表示 |
| 通知のON/OFF | 設定画面からいつでも切り替え可能 |

## 3. 非機能要件

### 3.1 対応環境

| 項目 | 内容 |
|------|------|
| 最小サポートOS | iOS 17以上（それ以下はApp Storeからダウンロード不可） |
| 対応デバイス | iPhone（iPad非対応） |
| 言語 | 日本語（初期リリース） |

### 3.2 パフォーマンス

- グリッド画面（4,160個の丸）を全件同時表示し、60fps以上でスムーズに描画できること（SwiftUI Canvasによる一括描画で実現）
- 壁紙画像のレンダリングは3秒以内に完了すること
- アプリ起動からグリッド表示まで2秒以内

### 3.3 データ・同期

- データはSwiftData + CloudKit経由でiCloud自動同期
- オフライン時はローカル保存し、接続回復時に自動同期
- 写真ライブラリへの保存にはユーザーの権限許可が必要（初回アクセス時にシステムダイアログ表示）
- 写真ライブラリ権限を拒否された場合は「設定を開く」誘導メッセージを表示し、アプリは継続動作する（2.9参照）
- 将来的な自前サーバーへの移行を想定したRepository抽象化設計

### 3.4 プライバシー・セキュリティ

- ユーザーデータは原則デバイス内 + iCloudに保存（外部送信なし）
- 写真ライブラリアクセス権限の用途を明示すること（App Storeの権限説明文）
- iCloudデータはAppleのセキュリティ基盤に準拠
- **認証・認可**: iCloud認証に委任。アプリ独自のログイン・セッション管理は不要（N/A）
- **パスワードポリシー**: iCloud認証のためアプリ固有のパスワードなし（N/A）
- **SQLインジェクション・XSS対策**: SwiftData（ORM）使用のためSQLiは構造的に対策済み。ネイティブアプリのためXSSは不適用（N/A）
- **エラー表示トーン**: エラー・警告メッセージはオレンジ系インフォトーンで統一。赤色・警告アイコン（⚠️）は使用しない

### 3.5 KPI計測要件

企画書で定義したKPIを計測するために必要なデータ仕様。

| KPI | 計測方法 | 必要なデータ |
|-----|---------|------------|
| 4週継続率（目標: 40%以上） | 初回WeekRecord作成から4週間以内に4件以上のWeekRecordが存在するか | `WeekRecord.createdAt`（作成日時）を保持すること |
| 初回記録完了率（目標: 60%以上） | オンボーディング完了後、最初のWeekRecord作成が完了するか | `UserDefaults: onboardingCompletedAt`（オンボーディング完了日時）を保持すること |

> 計測はアプリ内の集計のみ（外部送信なし）。SwiftDataの`WeekRecord.createdAt`はデフォルトで保持される。

### 3.6 N/A項目（個人アプリのため対象外）

| 項目 | 理由 |
|------|------|
| 可用性・稼働率 | サーバーを持たないため概念が適用されない |
| スケーラビリティ数値 | 初年度SOM 1,000〜5,000人規模。SwiftData + iCloudで十分対応可能 |
| 管理画面・運用機能 | 個人開発・個人利用のため不要 |

### 3.7 制約・前提

- iOSの制約上、アプリから直接壁紙を変更するAPIは非公開のためApp Store審査でリジェクト対象
- ショートカットApp連携（AppIntents）が唯一のApp Store安全な壁紙自動化手段
- ウィジェットは採用しない
- 壁紙自動更新はショートカットAppに依存するため、ユーザーの初回設定が前提
