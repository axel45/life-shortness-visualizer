# フェーズ4：実装 レビューチェックリスト

`/dev` が自動評価に使用する。`- [ ]` は未評価、`- [○]` は合格、`- [!]` は指摘あり。

---

## A. 機能完全性

- [ ] 設計書に定義された全エンドポイントが実装されているか
- [ ] 全画面設計に対応する画面・コンポーネントが実装されているか
- [ ] オンボーディング〜コアフローがローカルで一通り動作確認できるか
- [ ] 管理画面・運用機能が実装されているか（または意図的にスコープ外と記録されているか）
- [ ] 設計書との乖離がある場合、その理由が記録されているか

## B. セキュリティ実装

- [ ] パスワードが適切なアルゴリズム（bcrypt・Argon2等）でハッシュ化されているか
- [ ] 認証トークンの有効期限・リフレッシュ機構が実装されているか
- [ ] 全ての入力値にバリデーションが実装されているか（サーバーサイドで必ず実施）
- [ ] SQLクエリにプリペアドステートメント・ORMが使用されているか（SQLインジェクション対策）
- [ ] レスポンスに不要な個人情報・内部情報が含まれていないか
- [ ] シークレット・APIキー・DB接続情報が環境変数で管理され、コードにハードコードされていないか

## C. エラー処理・堅牢性

- [ ] 外部API・DB接続失敗時のエラーハンドリングが実装されているか
- [ ] バリデーションエラーのメッセージがユーザーフレンドリーな日本語で表示されるか
- [ ] 予期しない例外がキャッチされ、適切なHTTPステータスコードで返却されているか
- [ ] タイムアウト処理が実装されているか（長時間処理・外部API呼び出し）
- [ ] 冪等性が必要な処理（決済・通知等）に重複実行防止が実装されているか

## D. コード品質

- [ ] 関数・変数名が意図を明確に表現しているか（省略しすぎない・冗長でない）
- [ ] 1関数が1つの責務を持っているか（Single Responsibility）
- [ ] ハードコードされた定数（文字列・数値）が定数ファイルや設定に切り出されているか
- [ ] コードの重複が適切にまとめられているか（DRY原則）
- [ ] N+1クエリ・不要なループ等の明らかなパフォーマンス問題がないか

## E. 環境・デプロイ準備

- [ ] `.env.example` 等で必要な環境変数が文書化されているか
- [ ] ローカル環境のセットアップ手順が記録されているか
- [ ] 本番環境と開発環境で設定が分離されているか
- [ ] マイグレーションファイルが適切に管理されているか（手動でのDBスキーマ変更がないか）

## F. UX実装品質

> 設計フェーズで決定したUX方針が実際に実装されているかを確認する。

- [ ] タップ領域が 44pt × 44pt 以上あるか（主要ボタン・アイコン）
- [ ] タップ後 0.4秒以内に視覚的フィードバックがあるか（ローディング・アニメーション等）
- [ ] ローディング中に画面が空白のまま放置されていないか（スケルトン・スピナーあり）
- [ ] エラーメッセージが「何が・なぜ・どうすれば」を含む日本語になっているか
- [ ] データが0件の場合の空状態UIが実装されているか（メッセージ＋次のアクション）
- [ ] 削除・破壊的操作に確認ダイアログまたは「元に戻す」機能があるか
- [ ] 主要なアクション完了時に成功フィードバック（ハプティクス・トースト等）があるか
